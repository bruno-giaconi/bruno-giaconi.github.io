Exploring an AI architecture on Azure

Curiosity was my starting point: how do you connect an AI model to an API, organise its workflow and run the whole system on Azure? I used a fictional administrative meeting as a practical example. The application produces proposed decisions and actions that the user can then approve or reject.

I built this practical example with AI assistance to explore the Azure environment and understand how its services can host an AI application. Using a small fictional meeting leaves room to explore the architecture without relying on real data.

Explore the code on GitHub ↗

From text to a human decision

FastAPI receives the request and starts the LangGraph graph. The Azure OpenAI model selects passage identifiers from the transcript. The service accepts only those references and assembles quotations from the source text.

If no deadline is given, the field stays empty. The graph then pauses at a review step and resumes when the user approves or rejects the draft. This separation between generation and decision is central to how the application works.

Identity, data and temporary resources

The container’s managed identity grants access only to the Azure OpenAI resource used for the experiment. No model API key is embedded in the public code.

The resource was located in Switzerland North. Global Standard deployments allow model processing outside that region, so the resource location does not guarantee exclusively Swiss processing. All data used in the experiment was fictional.

The temporary Azure resources were deleted after the experiment. The portfolio remains a GitHub Pages site presenting this work; it does not make any model calls.

Explore the project yourself

The repository contains the FastAPI and LangGraph code, tests, Dockerfile, Kubernetes manifest, Bicep template and setup guide. Deterministic mode lets you start locally without a model provider account or an Azure service.

python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
python -m uvicorn pv_demo.api:app --host 127.0.0.1 --port 8000

In a second terminal, python scripts/smoke.py exercises the HTTP routes through to draft approval.
