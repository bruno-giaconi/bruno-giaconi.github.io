PERSONAL PROJECT · AI & workflow

A verifiable AI workflow, from API to Azure container

This prototype turns a transcript into decisions and actions whose sources can be checked. It demonstrates a reproducible workflow, from the API to execution in an Azure container.

What is the application for?

The prototype turns a fictional transcript into decisions and actions for review. Each item retains a source reference and its original quotation. The result remains pending until a user explicitly approves or rejects it.

The user journey

  1. 01

    View the reference transcript

    The API exposes the fictional scenario as individually identified passages. This shared source makes the results verifiable and the test reproducible.

  2. 02

    Prepare a draft

    An API call starts the LangGraph graph. The extraction mode is specified: a deterministic scenario for tests, or an Azure OpenAI model for live inference.

  3. 03

    Link each item to its source

    The model selects passage identifiers in a structured format. The service validates those identifiers and reconstructs quotations from the transcript instead of accepting fabricated quotations.

  4. 04

    Check deadlines

    A date is retained only when it appears explicitly in the source passage. If no date is given, the deadline field stays empty.

  5. 05

    Require a human decision

    The graph pauses at the review step. The user approves or rejects the draft through a separate action. A second review of the same draft is rejected.

  6. 06

    Reproduce the execution

    The repository contains the tests, Docker image and HTTP verification workflow. The same container was tested on Kubernetes kind, then on Azure Container Instances with a managed identity.

What makes it useful

Traceable results

The reference and quotation let you return to the information supporting each decision or action.

Human approval built into the workflow

Review is a blocking step in the graph, with an explicit state, rather than simply an instruction in the generated text.

Structured, validated output

The service validates the response contract and rejects unexpected references. Dates and quotations are derived from the source.

A reproducible deployment

The CI pipeline runs eleven tests, builds the image and verifies the HTTP workflow in an ephemeral cluster before publishing the container.

Azure integration without an embedded API key

The Azure Container Instances test uses a managed identity with an inference role scoped to the relevant model resource.

Current scope

This is a personal prototype based on a fictional scenario. State is kept in memory in a single instance. The Azure test resources were deleted after verification. The portfolio presents the architecture and checks. The AKS Bicep template was compiled, but AKS was not deployed.

My contribution

I built this prototype with AI assistance to document the workflow, tests, containerisation and a live Azure test.

What I built

  • A FastAPI service and LangGraph graph that prepare a draft, check its references, then pause processing for human approval.
  • An Azure OpenAI call with structured output. The model selects passages; the service verifies their identifiers and reconstructs quotations from the sources.
  • Explicit handling of a missing deadline, which is left empty, and a date present in the transcript.
  • A GitHub Actions pipeline with eleven tests, a Docker build, Kubernetes deployment on kind and HTTP workflow verification.
  • Execution of the same image in Azure Container Instances, with no public IP address, a managed identity and live GPT-4.1 mini inference.

What the project offers

An example with source code, tests and results available for review, clearly separating generation, source verification and human decision-making.
