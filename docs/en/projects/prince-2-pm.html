Prince 2 PM, an application for managing projects

Managing a transformation means connecting objectives, stakeholders, findings, decisions and actions. Prince 2 PM organises this work into a guided journey, from initial scoping to review, supported by the documents needed for decision-making.

What is the application for?

Prince 2 PM supports project work from initial scoping to final review. In one workspace, users bring together context, stakeholders, findings, risks, decisions, actions and reference documents. Records are linked: a documented finding can lead to a risk, a decision and then an action assigned to an owner. The six-stage journey remains flexible. Users can build their project information progressively, find points that need clarification and prepare decision packs from information already entered.

The user journey

  1. 01

    Define the assignment

    Clarify expected outcomes, scope, exclusions, sponsor, resources and decision-making authority. Assumptions, budget and tolerances establish a shared project framework. This information feeds into the project brief.

  2. 02

    Connect the stakeholders

    Identify organisations and their contacts, then describe how they interact. Each interface records the information needed, the expected output, the approval process and the person to contact if progress is blocked.

  3. 03

    Build the diagnosis

    Record a situation, its consequences and supporting evidence. Distinguish reported information from verified facts and retain assumptions that need confirmation. Risks combine probability, impact, ownership and mitigation measures to help set priorities.

  4. 04

    Design the solutions

    Compare scenarios by benefits, cost, effort, feasibility and conditions for success. Define RACI responsibilities, deliverables and acceptance criteria, followed by indicators to assess the project’s effects.

  5. 05

    Decide and plan

    Prepare options for a decision, identify the decision-maker and retain a reference to their decision. Translate choices into actions with owners, dates and dependencies. Assess changes and their impact on resources, scope and deadlines.

  6. 06

    Deliver and learn

    Track actions, deliverable verification, indicator results and deviations. Document acceptance, lessons learned and handover. Each stage has four checkpoints to keep outstanding items visible.

What makes it useful

Continuity across project information

Stakeholders, documents, decisions and actions link to the same records. In the fictional demonstration project, a document versioning issue is linked to a migration risk, a pilot decision and acceptance testing actions. Users can trace the context behind a choice and the work it creates.

Ready-to-assemble project packs

Eight PDF formats reuse project data: executive summary, project brief, stakeholders and interfaces, diagnosis, target solution, decision briefing, progress report and complete project pack. Users choose which registers, names and contact details to include, then download the pack or save it with their documents.

Documents and their context kept together

PDFs, Word and Excel files, text documents and images can be uploaded, classified, searched and linked to records. Originals remain accessible. The extraction status shows which text is usable, partial or still needs to be read in the original document.

Explicit preparation for AI analysis

Users select relevant documents and prepare an archive containing the originals and structured project context for their ChatGPT account. An MCP connector also provides direct access to authorised projects, records and extracted text. Analysis remains grounded in the selected information.

Review proposals before adding them

Analysis can produce proposed findings, risks, assumptions, scenarios and actions in JSON format. An interface lets users review, correct and select these proposals before creating records. Their origin is retained, and links to stakeholders or documents can be completed within the project.

Separate workspaces and responsibilities

The application manages client workspaces and administrator, contributor and reader roles. Permissions are checked on the server, including for the MCP connector. Support access to another workspace uses an explicit, logged session.

Attention to the quality of project information

The dashboard flags overdue dates and missing information: an owner, a date, evidence for a finding, acceptance criteria or an approval reference. Records offer search, filters and additional fields to adapt tracking to the project context.

A record of changes and recoverable data

The audit log records who created, edited or archived items and when, including before and after states. Archived records and documents remain recoverable. Data can be exported as JSON or in an archive with the documents. Revision checks flag concurrent edits.

An end-to-end example

In the fictional “Document Portal Modernisation” project, a finding about document versions leads to a risk of incomplete access permissions. A decision limits the pilot to one library and two teams. Actions, owners, deadlines and acceptance criteria then turn that choice into practical work.

Current scope

The screenshots show the actual application using an entirely fictional document management project in a local preview. The journey is inspired by PRINCE2. Users complete checkpoints and approvals. AI analysis takes place in the user’s ChatGPT account, while the MCP connector exposes five read operations. Proposals are added after review. The current extraction process handles text contained in files. Scans and images may require reading the original, and Excel formulas are not recalculated. Report privacy options apply to structured fields. Free text still needs to be reviewed before sharing.

My contribution

I design and develop this personal application with AI assistance. I structure the workflows, data model and access rules to connect the information needed for project management.

What I built

  • A six-stage journey: define the assignment, connect stakeholders, build the diagnosis, design solutions, decide and plan, then deliver and learn.
  • Linked records for organisations, risks, assumptions, solutions, responsibilities, decisions, actions and indicators. Each stage prepares a project management deliverable.
  • A TypeScript/React interface and SQL data, with documents attached to projects, text extraction and PDF pack generation.
  • Server-side management of client workspaces, roles, record versions and an audit log.
  • An MCP interface for reading authorised projects, records and documents, with pagination and partial extraction notices. Documents are treated as sources to analyse.

What the project offers

A workspace that connects project management information, supports decision-making and makes project context available to assistance tools within an authorised scope.
