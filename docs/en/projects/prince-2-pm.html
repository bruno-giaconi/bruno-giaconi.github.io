What is the application for?

At each stage, P2PM helps users ask the right questions and keep the answers in one place. The project connects its objective, stakeholders, findings and the choices that follow. Users can move freely through the six stages, build up information gradually and prepare deliverables from work already entered. The current framework draws on PRINCE2 7 and adapts to the project context.

The user journey

  1. 01

    Define the assignment

    Give the project direction: expected outcome, scope, sponsor, resources and decision limits. The project brief, assumptions and budget help clarify open questions. Outcome: a scoping document that establishes a shared mandate and management rules.

  2. 02

    Connect stakeholders

    Understand who is involved and how information should flow. Organisation, person, interface and meeting records clarify roles, expected information and approval paths. Outcome: a stakeholder map showing who to involve and whom to contact when progress is blocked.

  3. 03

    Build the diagnosis

    Start from facts to understand difficulties and their effects. Findings connect situations to evidence; assumptions keep uncertainty visible; risks combine probability, impact and a planned response. Outcome: an evidence-based diagnosis and priorities to discuss with those involved.

  4. 04

    Design the solutions

    Compare options before committing. Scenarios examine benefits, cost, effort and feasibility; the RACI matrix clarifies responsibilities; deliverables and indicators define results to verify. Outcome: a target solution with practical criteria for assessing its success.

  5. 05

    Decide and plan

    Turn options into decisions and organised work. Decision, action, change, budget and exception registers connect choices, owners, deadlines and dependencies. Outcome: a decision briefing and delivery plan with traceable commitments.

  6. 06

    Deliver and learn

    Track delivery and verify the effects achieved. Actions, deliverables, indicators, risks and lessons learned help identify deviations, record acceptance and prepare handover. Outcome: a project review with lessons learned and follow-up work after closure.

What makes it useful

A framework for steady progress

Each stage asks a clear question and provides four checkpoints. Guidance and missing-information alerts help users build the project record without needing every answer at the outset.

Trace the reasoning behind a decision

A finding can link to supporting documents, the risk it reveals, a decision and the resulting actions. The team can trace the context behind a choice and the responsibilities attached to it.

The right view for the question

Stakeholder maps, RACI, scenario comparisons, kanban, calendar and an interactive Gantt chart offer different views of the same records. Moving dates in the schedule updates the linked items.

Access aligned with responsibilities

Account administrators, internal users and external contributors have distinct access. Invitations and project- or item-level sharing define their scope. The server rechecks permissions, including during assistance.

A history of changes and recoverable data

The activity log connects each action to its author, workspace and project. Revision checks protect concurrent edits; archiving, restoration and exports help preserve and recover work.

Assistance within the project

The user books an available slot. After admission, the operator assists them in a shared workspace using the user’s effective permissions. Microphone and camera are optional; session activity is logged.

Documents that support the project

Documents support reasoning and decisions. P2PM brings sources together, shows what can be analysed and turns project information into packs that can be shared.

Collect documents and connect them

Store project files, including presentations and drawings, then classify them and link them to relevant records. Originals remain downloadable; text extraction depends on the file format and content.

Know which text is available

Extraction prepares usable text and indicates whether the result is complete, partial or unavailable. PDF text retains page references. This status helps identify documents that need to be read in their original form, particularly scans and images.

Choose sources and review AI analysis

Select the relevant brief, records and documents, check what will be sent, then run the analysis through an authorised API connection. Results are kept in a private history; a person reviews and selects proposals before integration. A real OpenAI call has been verified on the demonstration project.

Compose the eight PDF packs

Executive summary, brief, stakeholders and interfaces, diagnosis, target solution, decision pack, progress or full report: each format reuses the project information. The PDF template supports a logo, colours, fonts, header and footer, with a preview before saving and optional cover and contents pages.

Integrated assistance, from booking to resolution

When a question holds up a project, the user can request help from an operator within P2PM. The session opens a shared workspace in the app, with the project context and the requester’s permissions.

Choose a 30-minute slot

The client sees the operators’ combined availability and selects a date and time. Each participant receives confirmation; the bell and calendar highlight unread appointments.

Join with your usual account

Both participants use their usual P2PM sign-in. The requester waits for the operator to admit them. They choose whether to use their microphone or camera before joining and can switch them off or on during the session.

Work together in the project

Cursor, navigation and text entry are shared between two participants. A click or keystroke automatically coordinates their interaction while preserving text already entered. The requester’s permissions and normal saving rules remain in effect.

Finish with explicit feedback

Session duration is tracked. The operator can ask the participant to confirm whether the issue is resolved, leaving a record of the assistance outcome.

Personal accounts, explicit permissions

Google and email/password sign-in use the same P2PM permissions. The email address is verified at activation; an activated account is not asked for an email code at every ordinary sign-in. Sensitive operations still require a separate confirmation. Passkeys and authenticator apps remain security options.

Sessions can be revoked, sign-in attempts are rate-limited and permissions are checked when data is read or written. API secrets are encrypted on the server and bound to their workspace. These mechanisms are tested and documented; no certified compliance or security audit is claimed.

A choice of methods in development

Scrum, HERMES and other frameworks are planned directions. The chosen principle is one method per workspace, retained by its projects. The currently available workflow remains the one inspired by PRINCE2 7.

Current scope

The anonymised screenshots show an earlier interface version. The dated milestones describe features delivered since then. The workflow draws on PRINCE2 7. Recorded approvals are neither electronic signatures nor software certification. AI connectors are configurable; compatibility and provider terms must be checked for the account used. A local model requires an authorised HTTPS gateway reachable by the server. Extraction depends on the text available in the files and does not replace reviewing the originals. Excel formulas are not recalculated. Free-text sections in PDFs should be reviewed before sharing. Assistance depends on network connectivity and browser permissions. Personal confirmation dialogs remain local; audio and video across different networks still require real-world validation.
