Le démonstrateur de relevé de décisions permet d’examiner une chaîne complète, depuis la transcription jusqu’à la validation humaine. Je l’ai construit avec assistance IA pour rendre mes choix techniques, le code et les essais consultables.

Ce projet personnel utilise une réunion administrative entièrement fictive. Son code, son jeu de données et ses tests permettent de reproduire le scénario de bout en bout.

Un workflow avec un point de contrôle humain

L’API FastAPI reçoit la demande et exécute un graphe LangGraph. En mode Azure OpenAI, le modèle sélectionne des identifiants de passages dans la transcription. Le service contrôle ces références et reconstruit les citations depuis le texte source.

Une échéance absente reste vide. Le traitement se suspend ensuite pour qu’une personne approuve ou rejette le brouillon. Le graphe reprend uniquement après cette décision explicite.

Identité, données et durée de l’essai

L’essai Azure utilisait une identité managée pour le conteneur et un rôle d’inférence à la portée de la seule ressource Azure OpenAI. Aucune clé de modèle n’est intégrée au code public.

La ressource était située en Suisse Nord. Le mode de déploiement Global Standard autorise un traitement du modèle hors de cette région ; cet essai ne démontre donc pas un traitement exclusivement suisse. Il utilisait uniquement des données fictives.

Les ressources Azure d’essai ont été supprimées après vérification. Le portfolio reste accessible sur GitHub Pages. Son aperçu de décisions affiche une sortie enregistrée de l’API, sans solliciter un modèle à chaque visite.

Reproduire le scénario

Le dépôt fournit le code FastAPI et LangGraph, les tests, le Dockerfile, le manifeste Kubernetes, le modèle Bicep et le guide d’exécution. Le mode déterministe permet de commencer sans compte de modèle ni service Azure.

python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
python -m uvicorn pv_demo.api:app --host 127.0.0.1 --port 8000

Dans un second terminal, python scripts/smoke.py vérifie le parcours HTTP. Le guide du dépôt détaille les prérequis, les étapes Docker/Kubernetes et l’activation facultative du modèle Azure.

Le service conserve son état en mémoire dans une seule instance. C’est un démonstrateur reproductible ; une exploitation durable demanderait notamment une persistance adaptée et une gestion des accès propre à son contexte d’utilisation.
