PROJET PERSONNEL · IA & workflow

Workflow IA vérifiable, de l’API au conteneur Azure

Ce démonstrateur transforme une transcription en décisions et actions dont les sources peuvent être contrôlées. Il présente une chaîne reproductible, de l’API à son exécution dans un conteneur Azure.

À quoi sert l’application ?

Le démonstrateur transforme une transcription fictive en décisions et actions à examiner. Chaque élément conserve une référence et sa citation d’origine. Le résultat reste en attente jusqu’à l’approbation ou au rejet explicite d’un utilisateur.

Le parcours utilisateur

  1. 01

    Consulter la transcription de référence

    L’API expose le scénario fictif découpé en passages identifiés. Cette source commune rend les résultats contrôlables et le test reproductible.

  2. 02

    Préparer un brouillon

    Un appel à l’API lance le graphe LangGraph. Le mode d’extraction est indiqué : scénario déterministe pour les tests ou modèle Azure OpenAI pour une inférence réelle.

  3. 03

    Relier chaque élément à son origine

    Le modèle sélectionne des identifiants de passages dans un format structuré. Le service valide ces identifiants et reconstruit les citations à partir de la transcription, au lieu d’accepter une citation inventée.

  4. 04

    Contrôler les échéances

    Une date n’est retenue que si elle figure explicitement dans le passage source. Sans date, l’échéance demeure vide.

  5. 05

    Soumettre à une décision humaine

    Le graphe se suspend à l’étape de revue. L’utilisateur approuve ou rejette le brouillon par une action séparée. Une deuxième validation d’un même brouillon est refusée.

  6. 06

    Reproduire l’exécution

    Le dépôt contient les tests, l’image Docker et le parcours HTTP de vérification. Le même conteneur a été testé sur Kubernetes kind puis sur Azure Container Instances avec une identité managée.

Des résultats traçables

La référence et la citation permettent de revenir à l’information qui fonde chaque décision ou action.

Une validation humaine intégrée au workflow

La revue est une étape bloquante du graphe, avec un état explicite, plutôt qu’une simple consigne dans le texte généré.

Une sortie structurée et contrôlée

Le service vérifie le contrat de réponse et écarte les références inattendues. Les dates et citations sont calculées depuis la source.

Un déploiement reproductible

La CI exécute onze tests, construit l’image et vérifie le parcours HTTP dans un cluster éphémère avant publication du conteneur.

Une intégration Azure sans clé embarquée

Le test Azure Container Instances utilise une identité managée avec un rôle d’inférence limité à la ressource de modèle concernée.

Périmètre actuel

Il s’agit d’un démonstrateur personnel sur un scénario fictif. L’état est conservé en mémoire dans une instance. Les ressources Azure du test ont été supprimées après validation. Le portfolio présente l’architecture et les vérifications. Le modèle Bicep AKS a été compilé, mais le déploiement AKS n’a pas été effectué.

Ma contribution

J’ai construit ce démonstrateur avec assistance IA pour documenter le workflow, les tests, la conteneurisation et un essai réel sur Azure.

Ce que j’ai construit

  • API FastAPI et graphe LangGraph qui préparent un brouillon, contrôlent les références puis suspendent le traitement pour validation humaine.
  • Appel Azure OpenAI avec sortie structurée. Le modèle sélectionne des passages ; le service vérifie leurs identifiants et reconstruit les citations depuis les sources.
  • Gestion explicite d’une échéance absente, laissée vide, et d’une date présente dans la transcription.
  • Pipeline GitHub Actions avec onze tests, construction Docker, déploiement Kubernetes sur kind et vérification du parcours HTTP.
  • Exécution de la même image dans Azure Container Instances, sans IP publique, avec identité managée et inférence réelle GPT-4.1 mini.

Ce que le projet apporte

Un exemple dont le code, les tests et les résultats sont consultables, avec une séparation explicite entre génération, vérification des sources et décision humaine.
